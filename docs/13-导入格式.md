# 导入格式

Wetrace Plus 根据文件扩展名和内容表头自动识别格式。可以一次选择多个文件，也可以上传保留原目录结构的 ZIP。

## 兼容矩阵

| 适配器 ID | 输入 | 关键字段 | 发送方向 |
| --- | --- | --- | --- |
| `chatlog-keeper-json` | `wechat_messages.json` JSON 数组 | `ts,sender,sender_wxid,chat_room,conversation_id,content,msg_type,is_self,account_id,thread_id,server_id,source_offset` | 精确 |
| `chatlog-json` | JSON 数组 | `seq,time,talker,talkerName,isChatRoom,sender,senderName,isSelf,type,subType,content` | 精确 |
| `chatlog-csv` | CSV | `Time,SenderName,Sender,TalkerName,Talker,Content` | 私聊可推断；群聊建议填写本人 ID / 昵称 |
| `memotrace-csv` | CSV | `消息ID,类型,发送人,时间,内容` | 建议填写本人昵称 |
| `memotrace-full-csv` | CSV | `localId,TalkerId,Type,SubType,IsSender,CreateTime,StrContent` | 精确 |
| `wetrace-plus-json` | JSON 对象 | 见下方标准 | 精确 |

CSV 表头匹配不区分大小写，并忽略空格、下划线和连字符。支持带 UTF-8 BOM 的文件。

## chatlog-keeper 微信 JSON

直接导入 `chatlog-keeper` 生成的 `wechat_messages.json`；配套 HTML 是浏览页面，不是数据源，无需上传。适配器使用账号隔离的 `thread_id` 建立会话，避免多账号导出时合并同名会话；并使用 `conversation_id`、`sender_wxid`、`is_self`、`msg_type` 和 Unix 浮点秒时间恢复会话、发送者、方向、原始消息类型和顺序。消息来源 ID 优先使用 `server_id`，缺省时使用 `source_offset`。

仓库提供了一份依据上游导出函数构造的[脱敏格式样例](../internal/importer/testdata/chatlog-keeper-wechat.json)，并将同一文件用于自动化回归测试。

当前 `chatlog-keeper` 的微信 JSON 只输出规范化后的文字 `content` 与 `msg_type`，没有输出附件路径或附件元数据。因此文字、会话、成员、时间、方向和类型可以直接接入；图片、语音、视频等只能保留其在 `content` 中的占位描述，不能从这个 JSON 还原原文件。

## Wetrace Plus JSON v1

```json
{
  "format": "wetrace-plus",
  "version": 1,
  "account": {
    "id": "wxid_me",
    "name": "我"
  },
  "conversations": [
    {
      "id": "wxid_friend",
      "name": "小明",
      "type": "direct",
      "messages": [
        {
          "id": "10001",
          "time": "2026-08-01T09:30:00+08:00",
          "sender_id": "wxid_friend",
          "sender_name": "小明",
          "direction": "incoming",
          "type": 1,
          "subtype": 0,
          "content": "早上好"
        },
        {
          "id": "10002",
          "timestamp": 1785547860,
          "sender_id": "wxid_me",
          "sender_name": "我",
          "is_self": true,
          "type": 1,
          "content": "早"
        }
      ]
    }
  ]
}
```

规则：

- 顶层 `format` 必须为 `wetrace-plus`，`version` 必须为 `1`。
- `time` 或 `timestamp` 至少提供一个，可使用 RFC 3339 字符串、常见本地日期时间、Unix 秒或 Unix 毫秒。
- `direction` 接受 `outgoing` / `sent` 表示本人发送；`is_self` 存在时优先级更高。
- 会话 `type` 为 `group`，或 ID 以 `@chatroom` 结尾时，按群聊处理。
- `type` 省略或小于等于 0 时按文本类型 `1` 处理。
- `id`、`seq`、发送者 ID 与昵称允许缺省，但稳定 ID 能改善去重和展示质量。

## ZIP 规则

- 只处理压缩包内的 `.json` 与 `.csv`，其他文件会跳过。
- MemoTrace 会话 CSV 会利用 `名称(wxid_xxx)/文件.csv` 目录名恢复稳定会话 ID，因此建议保留原目录结构。
- 单个压缩包内文件和总解压量受安全上限限制。
- 任何一个受支持文件解析失败时，本次导入事务整体回滚。

## 去重

消息指纹由会话 ID、精确时间、发送者、发送方向、消息类型、子类型和内容共同计算。同一批或后续批次中的相同消息会跳过；来源文件本身不会被永久复制。

## 当前限制

- 不直接导入 HTML、TXT、PDF 或微信数据库文件。
- 旧式 CSV 没有稳定会话 ID 或发送方向时只能做尽力推断。
- 当前适配层优先导入消息与关系元数据；`chatlog-keeper` 微信 JSON 本身不包含附件文件或路径，因此不能还原图片、语音和视频原件。
- 导出工具更新字段后，可能需要新增或调整适配器。欢迎提交脱敏后的最小样例与测试。
